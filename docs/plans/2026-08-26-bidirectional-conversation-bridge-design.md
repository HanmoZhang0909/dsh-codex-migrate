# dsh-codex-migrate v0.2 双向会话桥设计

状态：已确认并冻结  
日期：2026-08-26  
目标版本：0.2.0

## 1. 目标

把现有的单向 Codex 迁移插件扩展为“迁移 + 共享会话桥”：Codex 与 DeepSeek
Harness（DSH）可以注册同一条逻辑对话、在任一端继续，并在单写约束下同步
对话、执行状态、Todo、项目上下文和持久记忆。

共享模式只同步对话。项目是注册、分组、默认记忆范围和侧栏状态的管理单位；
项目文件的实时同步不属于 v0.2，原有迁移时复制项目文件的功能保持独立。

## 2. 冻结范围

### 2.1 注册

- 非项目对话支持一次操作注册当前对话。
- 项目内支持“注册整个项目”或“手动选择对话”。
- 所有选中对话立即在另一端创建对应会话，不延迟创建。
- “整个项目”是持续规则，之后新建的项目对话自动加入。
- “手动选择”只包含被选中的对话，之后新对话不自动加入。
- 解除共享是普通操作，不归入危险操作。

### 2.2 继续与同步

- Codex 通过提示词“在 DSH 继续”调用伴生 MCP，不注入 Codex 原生界面。
- DSH 在原生消息操作行提供“在 Codex 继续”。
- 默认同步频率：任务结束时提交；没有任务模式时，每轮对话结束提交。
- 可选高频模式：Agent 每发送一条消息就提交一次对话增量。
- 创建分支时询问是否同步；确认后立即在另一端创建对应分支。
- 删除不直接传播。默认手动归档，可选自动归档；不跨端永久删除。

### 2.3 单写与冲突

- 同一共享对话任何时刻只有一个写入端，使用带心跳和过期时间的执行租约。
- 另一端可查看实时状态、Todo 和最近消息，但不能同时推进。
- 正常接管必须先释放原写入端租约，再授予新写入端。
- 如果双方意外越过同一公共修订，系统在第一条不同消息处进入冲突状态。
- 用户选择 Codex 或 DSH 版本后，选中版本成为唯一可见历史。
- 被放弃版本仅留在内部恢复日志中，不生成第二条活跃对话。

## 3. 高层架构

```text
┌──────────────────────┐
│ Codex companion MCP  │
│ tools + status card  │
└──────────┬───────────┘
           │ loopback RPC + install token
┌──────────▼──────────────────────────────────┐
│ Shared Conversation Core                    │
│ registry │ event journal │ lease │ conflict │
│ sync engine │ memory provider adapters      │
└──────────┬──────────────────────────────────┘
           │ DSH service API / conversation events
┌──────────▼───────────┐
│ DSH host + web UI    │
│ adapter + sidebar UI │
└──────────────────────┘
```

伴生 MCP 默认随 DSH 插件启动，同时保留独立启动入口。两种启动方式使用同一协议、
同一状态目录和同一安装令牌。

## 4. 共享会话模型

`SharedConversation` 至少包含：

| 字段 | 含义 |
| --- | --- |
| `bridgeId` | 稳定逻辑会话 ID |
| `codexConversationId` / `dshConversationId` | 两端物理会话 ID |
| `projectKey` | 可空的项目范围 |
| `registrationMode` | `single` / `project_all` / `selected` |
| `status` | `ready` / `pending` / `running` / `paused` / `error` / `conflict` |
| `activeSide` | `none` / `codex` / `dsh` |
| `lease` | owner、token、acquiredAt、heartbeatAt、expiresAt |
| `revision` | 当前规范历史修订号 |
| `lastCommonTurnId` | 双端最后共同轮次 |
| `syncPolicy` | `task_turn` / `agent_message` |
| `archivePolicy` | `manual` / `automatic` |
| `memoryProviderId` / `memoryCursor` | 记忆提供者与增量游标 |

所有状态变更先写追加式 JSONL 事件日志，再原子更新物化状态文件。事件带
`eventId`、`bridgeId`、`baseRevision` 和幂等键，重复投递不重复生成会话轮次。

## 5. 状态与界面

### 5.1 DSH 侧栏

| 状态 | 显示 |
| --- | --- |
| 普通未共享 | 保持原图标 |
| 正常共享或同步 | 蓝色云朵 |
| 暂停 | 黄色云朵 |
| 错误或冲突 | 红色云朵 |

项目级共享把项目文件夹图标替换为云朵；单对话共享在对话标题前显示云朵。
颜色只表达共享对话状态，不表示项目文件正在同步。

### 5.2 Codex 侧

- 未活动时不显示常驻按钮。
- DSH 活动时，当前对话末尾只保留最新一张全宽状态卡。
- 卡片填满 MCP 内联区域，不露出外围黑底。
- 卡片显示真实 Todo、最近状态消息和当前操作。
- 卡片保留“在 DSH 打开”和“停止并接管到 Codex”。
- `ready`、`paused` 和完成状态隐藏卡片；`pending`、`running`、`error` 显示。
- 不使用 PiP、窗口覆盖、坐标定位、右栏注入或 Codex DOM 扫描。

## 6. 记忆提供者设计

### 6.1 能力发现与选择

桥不绑定某个 Skill 名称，而是发现 MCP 工具与资源能力。选择顺序为：

1. 用户明确选择的提供者；
2. 来源端当前已经在使用并且支持读、写、搜索的 MCP 记忆提供者；
3. 已注册的兼容提供者；
4. 伴生 MCP 内置的 JSONL 记忆提供者。

首批适配器：

- AgentMemory：增强适配器，利用保存、搜索、会话和生命周期能力。
- 官方 `@modelcontextprotocol/server-memory`：基础知识图谱适配器。
- Neo4j Agent Memory：可选高级适配器，不作为默认依赖。
- 文件式 `~/memory/` Skill：只有在其主动注册 MCP 能力后才直接复用；否则可由
  用户显式导入，桥不直接扫描任意 Skill 私有目录。

如果没有兼容提供者，`dshCodexBridge` 在同一个 MCP 中创建默认提供者，数据写入
`<outputDir>/bridge/memory.jsonl`，并向 Codex 与 DSH 暴露统一的保存、搜索、读取和
删除接口。

### 6.2 记忆范围

- 独立对话默认使用 conversation scope。
- 项目对话默认使用 project scope。
- global scope 必须显式开启，不能自动把全部个人记忆带入共享项目。
- `AGENTS.md` 始终作为项目指令独立继承，不混入持久记忆实体。

### 6.3 同步频率

记忆同步不是一次性复制，也不是每条消息全量复制：

1. **首次注册**：执行一次 bootstrap，记录提供者、范围、当前修订和相关记忆摘要。
2. **正常运行**：只发送 `memory.upsert`、`memory.delete` 等增量事件。
3. **默认提交点**：任务结束或一轮对话结束。
4. **显式记忆**：用户或 Skill 明确调用“记住”时立即提交。
5. **高频模式**：只提高已经确认的记忆变更提交频率，不把所有原始消息保存为记忆。
6. **刷新**：优先订阅 MCP resource update；不支持订阅时，在继续/接管时比较游标。

同一个提供者被两端共用时不复制存储，只同步 provider ID、scope 和 revision cursor。
提供者不同才通过规范化增量事件转换。

### 6.4 记忆冲突

- 新增的原子 observation 可以合并。
- 对同一稳定 memory ID 的修改使用 `expectedRevision`。
- 修订不匹配时不采用静默 last-write-wins，而是记录冲突并等待选择。
- 删除写 tombstone，避免离线端重新引入已删除记忆。

## 7. 设置页与性能

- 语言选择立即重渲染页面；`Auto` 跟随 DSH，选择中文或 English 后立即生效。
- 设置页重新整理为数据源、迁移、共享会话、范围、记忆、日志和高级选项。
- 不增加固定顶部状态与三个动作；当前状态进入日志。
- 清空导入需要二次确认，但不增加“危险操作”标题。
- 清单首次加载使用缓存，刷新只解析 mtime/size/hash 变化的会话文件。
- 项目和会话长列表采用分批或虚拟渲染。
- 轮询状态不触发清单扫描。
- README 横幅压缩并使用仓库相对路径，保留可直接打开的资源链接。

## 8. 非功能要求

- 纯本机桥调用 p95 小于 100 ms（不含 Agent 推理时间）。
- 未变化目录的清单刷新目标小于 500 ms；只处理变化文件。
- 事件日志先于物化状态写入，进程退出后可重放，目标 RPO 为 0 个已确认事件。
- 服务只监听 `127.0.0.1`，每次安装生成随机令牌；修改请求必须认证。
- 状态、日志和记忆使用原子写入；不引入必须编译的本机数据库依赖。
- DSH 未运行时，伴生 MCP 能以独立模式提供注册、状态和内置记忆能力。

## 9. 故障处理

| 故障 | 行为 |
| --- | --- |
| DSH 离线 | 本地排队增量，状态黄色；超时后红色，不丢事件 |
| MCP 记忆提供者离线 | 保留 memory cursor 与待提交事件，恢复后按修订重放 |
| 租约心跳丢失 | 先暂停，等待租约过期或用户显式接管 |
| 双端分歧 | 红色冲突状态，在第一处差异选择规范版本 |
| 状态文件损坏 | 从 JSONL 事件日志重建物化状态 |
| 重复事件 | 使用 eventId 和幂等键忽略重复投递 |

## 10. 明确不做

- 不注入 Codex 原生界面。
- 不实时同步项目文件。
- 不允许双端同时写入。
- 不实现自动语义合并或 CRDT。
- 不自动传播永久删除。
- 不在主界面展示多版本树。
- 不把每条普通对话消息自动升级为持久记忆。

## 11. 验收标准

- 单对话、整项目和手动选择三种注册路径均可建立稳定双端映射。
- 任何时刻只有一个写入端；并发测试能稳定进入冲突而非静默覆盖。
- 两种同步频率均通过端到端测试。
- 归档、分支、接管、离线恢复和重复事件均可复现并验证。
- 有现成 MCP 记忆时复用；没有时自动启用内置提供者。
- 首次记忆 bootstrap 后只产生增量事件，未修改记忆不会重复写入。
- Codex 状态卡与 DSH 云朵状态来自同一条真实共享记录。
- 语言切换立即生效，未变化清单刷新达到性能目标。
